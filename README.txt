CampusPilot - Lost & Found Integration
======================================

This folder contains the frontend components for integrating the Lost & Found system into the existing CampusPilot Lost & Found page.

The CampusPilot header, left navigation bar, and right schedule panel should remain unchanged.
The components in this folder are intended to be placed only inside the main center content area of the CampusPilot Lost & Found page.


1. FILES
--------

src/
  LostFoundContent.jsx
  StudentView.jsx
  AdminView.jsx
  ItemCard.jsx
  lostfound.css


2. MAIN COMPONENT
-----------------

LostFoundContent.jsx is the main component.

Import it into the existing CampusPilot Lost & Found page:

import LostFoundContent from './path/to/LostFoundContent'

Then render it inside the CENTER CONTENT AREA:

<LostFoundContent />

Do not replace the existing CampusPilot header, sidebar, or schedule panel.


3. STUDENT / ADMIN TABS
-----------------------

LostFoundContent contains two tabs:

- Student
- Admin

The tabs switch the content inside the same CampusPilot Lost & Found page.

StudentView.jsx:
- Search lost/found items
- Filter by category
- Filter by All / Pending / Completed
- Display Item No.
- Display item name, category, location, date found, description, image, and status

AdminView.jsx:
- Register new items
- Automatic Item No. (generated by Django)
- Edit items
- Delete items
- Change Pending / Completed status
- Record claim information
- Display UNID, Claimed Date, and Admin Note for completed items


4. API ENDPOINTS
----------------

The components currently expect these Django API endpoints:

Public:
GET /api/items/
GET /api/items/<id>/

Admin:
GET  /api/admin/items/
POST /api/admin/items/
PATCH /api/admin/items/<id>/
DELETE /api/admin/items/<id>/
PATCH /api/admin/items/<id>/complete/


5. IMPORTANT: BACKEND CONNECTION
--------------------------------

The current API paths are relative paths such as:

/api/items/
/api/admin/items/

These work in the original Lost & Found development environment because Vite proxies /api requests to the Django backend.

CampusPilot is hosted on GitHub Pages.

GitHub Pages cannot provide the same Vite development proxy.

Therefore, before production deployment, CampusPilot must either:

1. Point these API requests to the deployed Django backend URL,

OR

2. Deploy the frontend and Django backend using a setup where /api requests are routed to Django.

The API base URL may need to be changed after the final Django backend URL is known.


6. ADMIN AUTHENTICATION
-----------------------

The current admin system uses Django session authentication.

In the original local environment, frontend and backend requests work through the same origin/proxy.

If CampusPilot and Django are deployed on different origins, admin authentication will require additional backend configuration such as CORS, CSRF trusted origins, and cross-origin cookie/session settings.

The preferred setup is to keep the frontend and Django API behind the same origin when possible.

9. BACKEND REQUIREMENT
----------------------

These frontend files do not include the Django backend.

A running/deployed Lost & Found Django backend is required for:
- Loading items
- Registering items
- Editing items
- Deleting items
- Updating status
- Saving claim details
- Admin authentication
